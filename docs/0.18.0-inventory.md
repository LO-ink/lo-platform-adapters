Inventory source: `zaytcevcom/lo-miniapp-sdk` `origin/main` at `15b832edfd03559b12cbb2e843141f10532f5c96`. Native behavior source: LO `miniapp-runtime` at `64c63e9e350ba35c6b96f037b6fab0b21f9047b2`.

The neutral contract targets the breaking `0.19.0` line. It does not reuse the `0.18.0` version for a different API. Registry publication is pending.

## Raw host surface

The former `HostSDK` also exposed APIs without top-level helpers. Every surface has a typed normalized operation in `MiniAppOperationMap` and a compatibility translation:

- lifecycle and chrome: ready, expand, fullscreen enter/exit, keyboard dismissal, orientation lock, closing confirmation, header/background/bottom colors;
- controls: back, main, secondary and settings buttons;
- interaction: haptics, popup, external link, data send, inline query, QR scanner;
- device: clipboard, location, biometry, accelerometer, gyroscope, device orientation, file download;
- invoice, storage, permissions and sharing listed above.

Normalized event coverage includes activation, theme, viewport, both safe areas, fullscreen, four buttons, QR, motion sensors, and device orientation. Subscription cleanup is deterministic.

## Protocol subpath

The old `protocol` entrypoint exported foreign outgoing/incoming wire enums and payloads (`MiniAppOutgoingEvent`, `MiniAppIncomingEvent`, bridge envelope, snake-case payloads, custom storage RPC payloads). Those exports are intentionally absent from the canonical SDK. The replacement exports normalized `Capability`, `MiniAppEventMap`, `MiniAppOperationMap`, snapshots, values, limits, and protocol version. Existing wire schemas remain at the app/adapter edge and are not claimed as LO's canonical public protocol.

## Known gaps in this slice

- Current LO adapter consumes `LO.WebApp`. Native LO bridge transport and app integration are not migrated.
- Current LO runtime advertises only features it actually ships; this repository does not raise that list.
- Popup, sensor, location, biometry, file-download, inline-query, QR, buttons, and chrome operations have typed adapter paths but do not yet have per-operation conformance tests against a shipped LO binary.
- Continuous QR callbacks are exposed as normalized events; no higher-level scanner session object exists yet.
- Existing direct consumers of `host.sdk` require migration to `client.call` or a facade. No foreign-shaped compatibility API is re-exported from core.
- Only ESM adapters are built in this slice. The SDK itself ships ESM, CommonJS, and declarations.
- The VK adapter exercises the same port with the official VK Bridge package, bounded initialization and normalized host events. Local fixtures do not establish live hosted VK authentication or full feature parity.
- Native authentication, permission enforcement, and server protocol remain app-owned and unchanged.
